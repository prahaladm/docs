  <Tab title="Studio">
    <Warning>
    **Correction to this page's original framing.** There is no visual "Studio data panel" for creating or editing tables. Confirmed live: **CONNECT → Database** is a one-button, credential-free authorization handoff to Supabase (no project URL, anon key, or service role field appears anywhere in the unlinked state) — and once linked, **schema work (creating tables, columns, indexes, RLS policies) is something you ask the AI Assistant for in plain English, not something you click through a Studio UI for.**
    </Warning>

    Connecting a backend: open **CONNECT → Database**. On an unlinked project you get a two-part empty state — a left panel reading *"No database connected"* and a card with a single **Connect Supabase** button. Clicking it hands off to Supabase's own site to authorize NativeFlow and pick or create a project.

    Once linked, the AI Assistant carries a `backend` tool group of **19 tools** covering: listing tables, creating a table, altering/dropping tables, enabling row-level security, creating and listing policies, creating indexes, an arbitrary SQL escape hatch, Supabase edge-function management, and two tools that turn a table or edge function into an entry in the **API Calls** pane. A few worth knowing as design decisions:

    | Tool | What it does |
    | --- | --- |
    | `get_backend_status` | Checks whether the project is linked at all — meant to be called before any other backend tool |
    | `create_table` | Always adds an `id uuid` primary key, `created_at`/`updated_at` with a trigger, grants to `authenticated` and `service_role`, enables RLS, and adds an owner-only policy if a `user_id` column exists |
    | `drop_table` | Destructive — requires explicit confirmation plus an `allow_destructive` flag |
    | `create_policy` | Creates one RLS policy, defaulting the role to `authenticated` |
    | `exec_sql` | The escape hatch — refuses DROP/TRUNCATE/DELETE unless `allow_destructive` is true |
    | `register_table_api` then `bind_api_to_component` | The explicit bridge from a table to a screen |

    So the practical path is: link Supabase once, then ask the AI Assistant for the table, the column change, or the policy in plain English. Data reaches a screen in three stages — create the table, register it as an API, then bind that API to a component — the same path a person takes by hand through **CONNECT → API Calls** (see the "API Binding" page).
