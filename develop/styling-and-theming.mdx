title: "Styling and Theming"
description: "Applying design tokens, text styles, and light/dark theme modes to a project."
---

<Tabs>
  <Tab title="Studio">
    Theming lives at **CONFIG → Theme Settings** (the palette icon). The pane itself is headed **Runtime Theme** — *"Drives the canvas and the exported app,"* distinct from the separate, agent-authored **Foundation → Design System** spec. It has four sub-sections down a left rail: **Colors**, **Typography & Icons**, **App Config**, and **Themed Components**.

    <Frame caption="Editing the Primary color token to orange and back on camera, then reading the Typography table and all three App Config tabs.">
      <video controls muted playsInline className="w-full aspect-video rounded-xl" src="/studio-guide/videos/theme-settings-demo.mp4"></video>
    </Frame>

    **Colors** groups 16 tokens into four sets — Brand (Primary/Secondary/Tertiary/Alternate), Semantic (Success/Error/Warning/Info), Utility (Primary Text/Background/Surface), Chart (Chart 1–5). Clicking a swatch opens a **Choose a Color** dialog with no Save button — the edit applies as you make it and reaches the canvas live, with no reload, for any component *bound* to that token (a component holding a literal hex color won't change). Every token also holds a separate value per mode (Light/Dark), and the Light/Dark toggle **only scopes which values you're editing** — it does not switch what the canvas renders.

    **Typography & Icons** is an 18-row style table (Display, Headline, Title, Label, Body, Overline, Caption) with, per row: an authored Mobile base size, derived Tablet/Desktop sizes (via a configurable multiplier), letter spacing, italic, a Weight dropdown, a Color dropdown of the project's own color tokens, and a Font Family dropdown (13 built-in fonts). Typography colors are token references, not literals — so a Colors edit flows through the type scale too. The "Icons" half of this pane's name is still unbuilt — it shows a **Coming Soon** placeholder.

    **App Config** holds the app shell: navigation chrome, native header, feedback/motion, breakpoints and scale — split across **Mobile** and **Common** tabs (on a Mobile-target project; a Web-target project is expected to additionally expose Web-specific navigation-chrome controls like Sidebar / Navbar / Drawer, not confirmed directly). Mobile covers tab-bar presence and style plus a full native header block (with a live phone preview). Common covers branding, the loading-indicator style, and — critically — the project's **breakpoints**, a four-stop slider at 0 / 479 / 767 / 991 (Desktop has no upper bound), plus independent Font-scale and Theme-scale multipliers for Tablet/Desktop tiers.

    <Warning>
    These App Config breakpoints are a **different vocabulary** from the per-component Responsive Visibility bands (Phone &lt;600px, Tablet 600–900px, Large Tablet &gt;900px). The numbers are broadly consistent when cross-checked against the Preview panel's three measured device sizes, but the *labels* are two separate systems — don't assume they're the same setting.
    </Warning>

    **Themed Components**, the fourth rail icon, is where these tokens actually get consumed by named, reusable component presets — worth documenting as its own page.
